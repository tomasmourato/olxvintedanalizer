# OLX + Vinted Deal Hunter

A PWA plus a home worker that polls OLX.pt and Vinted.pt for PC parts and sends web-push alerts for great deals. Built for a friend who resells PCs.

- Plan: `PLAN.txt` in the repo root (local copy, gitignored — it holds the pricing, never commit it) or `C:\Users\mrttm\.claude\plans\contexto-um-amigo-est-zazzy-clock.md` (phases F0–F7). F0 findings: `docs/F0-validacao.md`.
- Stack: `apps/worker` (Node 24 + TS, Playwright/Edge for OLX, plain fetch for Vinted, runs on the friend's home PC via pm2), `apps/web` (Vite + React + Tailwind PWA on Cloudflare Pages), `packages/shared` (DB types + shared logic, consumed as TS source), `supabase/` (Postgres, RLS, pg_cron). AI deal scoring: Gemini 3.5 Flash-Lite (free tier, ~1 s; 3.8 Flash took 4 s+) with a rules fallback.
- Repo: github.com/tomasmourato/olxvintedanalizer (private). CI: `.github/workflows/ci.yml` runs typecheck, test and web build.
- Supabase project `pcdealhunter`, ref `suldkcbhpmvhpxksrlot` (linked). Schema: `supabase/migrations/`. Public sign-ups are off.
- Secrets live only in gitignored files: root `.env` (`SUPABASE_DB_PASSWORD` for the CLI) and `apps/worker/.env` (URL + secret key). The web publishable key is committed in `apps/web/src/lib/supabase.ts` (public by design).
- Commands: `npm run typecheck`, `npm test`, `npm run build:web`, `npm run db:types` (regenerate `packages/shared/src/database.types.ts` after a migration), `npx supabase db push` (needs `SUPABASE_DB_PASSWORD`).
- Worker (`apps/worker`): `npm run dry -w @dh/worker` (one cycle, no DB writes), `npm run once -w @dh/worker` (one cycle, writes), `npm start -w @dh/worker` (loop). Pipeline: `scheduler.ts` → `sources/*` → `pipeline/store.ts` (dedup via unique index) → `pipeline/match.ts` (title-only terms) → `pipeline/process.ts` (Vinted enrichment: seller country via users API, catalog + description via item page, spaced 1.5 s because the users API 429s on bursts). First fetch of a new scope is "silent" (stored, not announced). Then `pipeline/evaluate.ts`: 30-day median of the watch's matches → `score.ts` rules (target price, median ±10, too-cheap = suspicious) → candidates (≥ `candidate_threshold`, not silent) go to `ai.ts` (Gemini, `GEMINI_API_KEY` in `apps/worker/.env` (the friend's key), optional `GEMINI_MODEL`, 4 s timeout, 10/min cap; failures fall back to rules, "(sem IA)") → tier from the score thresholds → `holdBack` (silent, OLX bumps > 24 h) → `src/push.ts` (web-push, one push per listing, respects `push_enabled`, logs `notifications`, sets `matches.notified`; wording in `pipeline/payload.ts`). `npm run test-push -w @dh/worker` sends a test push from the worker.
- Push: VAPID keys in `apps/worker/.env`; the public key is also in `apps/web/src/lib/push.ts`. PWA = vite-plugin-pwa injectManifest with `apps/web/src/sw.ts` (precache + push/notificationclick) and `components/PushCard.tsx` (enable, test, iPhone install steps). The `push` Edge Function (`supabase/functions/push`, deploy with `npx supabase functions deploy push --use-api --no-verify-jwt`; secrets `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `PUSH_FN_SECRET`) sends the PWA's test push (user token) and the watchdog alert: pg_cron `worker-watchdog` every 5 min runs `public.worker_watchdog()` (active hours, no heartbeat for 10 min, once per outage) → pg_net with the Vault secret `push_fn_secret` (= `PUSH_FN_SECRET`).
- Web (`apps/web`): hash routes `#/negocios`, `#/pesquisas[/nova|/<id>]`, `#/alertas`, `#/logs`, `#/definicoes` (tab bar in `App.tsx`, screens in `src/pages`). Data via `lib/live.ts` (`useQuery` + `useRealtime` on the tables in the `supabase_realtime` publication, reload when the app returns to the foreground); category id names in `lib/categories.ts`; pt-PT number formatting and active hours are shared (`fmtEuros`, `isActive` in `@dh/shared`). Local preview: `.claude/launch.json` "web" (port 5173, needs the user's login). `window.scrollTo` returns a Promise in recent Chromium, so never return it from a `useEffect`.
- `npx supabase db query --linked "<sql>"`: use one statement per call when writing (a multi-statement update did not persist).
- Careful: `supabase config push` applies without asking (preview with `supabase config diff`). Keep `[auth.email] enable_signup = true`: false disables email logins entirely; sign-ups are blocked by `auth.enable_signup = false`. Email confirmations are off so email changes apply immediately (the app re-checks the password).
- User rules: never create accounts; stop and ask for any login/key. The user is on Claude Pro, so keep sessions lean (one phase per session, no subagents).
- UI language: Portuguese (pt-PT).
